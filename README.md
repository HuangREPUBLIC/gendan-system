# 跟单系统 · 服装生产跟单打卡系统

公司内部使用的生产进度跟踪工具，替代 Excel 表格手工记录订单进度的方式。

下厂员在工厂现场随时打卡记录工序进度，业务员和管理员**在各自的手机/电脑上同时看到最新情况**，减少电话沟通和手工登记表格的成本。

- 手机、电脑都能正常使用（响应式设计）
- 真正的服务端 + 数据库，多人多设备共享同一份数据
- 界面：简洁商务风，主色调韩式蓝（参考大韩航空）

---

## 快速开始

需要 **Node.js 22 或更高版本**（用到了 Node 内置的 `node:sqlite`，无需安装数据库）。

```bash
git clone https://github.com/HuangREPUBLIC/gendan-system.git
cd gendan-system
npm install
npm start
```

浏览器打开 <http://localhost:3000> 即可。

首次启动会自动建库并填充演示数据，演示账号（密码均为 `123456`）：

| 角色 | 手机号 |
|---|---|
| 管理员（老板） | 13800000000 |
| 业务员 | 13811112222 / 13833334444 |
| 下厂员 | 13855556666 / 13877778888 |

> **正式启用**：跑一条命令清掉演示数据，只留你自己的管理员账号：
>
> ```bash
> npm run init-admin -- --name 你的姓名 --phone 你的手机号
> ```
>
> 默认初始密码 `123456`，登录后请到「我的」里立刻改掉（也可以加 `--password 自定义密码`）。
> 想保留已录入的订单就再加 `--keep-orders`。

### 让手机也能访问

同一个 WiFi 下，用电脑的局域网 IP 访问即可，例如 `http://192.168.1.10:3000`。
（macOS 查看 IP：`ipconfig getifaddr en0`）

放到公司服务器上长期运行，推荐用 pm2：

```bash
npm install -g pm2
pm2 start server/index.js --name gendan-system
pm2 save && pm2 startup
```

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 服务端口 |
| `DATA_DIR` | `./data` | 数据目录（SQLite 数据库 + 上传的款式图），部署时可指向独立磁盘/数据卷 |
| `JWT_SECRET` | 自动生成并保存在 `DATA_DIR/.jwt_secret` | 登录令牌密钥 |

> **备份**：把 `DATA_DIR` 整个目录复制走即可，里面就是全部数据。

## 角色与权限

权限全部在**服务端**强制校验（前端只是隐藏按钮，改不了实际权限）。

| | 管理员 | 业务员权限 | 下厂员权限 |
|---|---|---|---|
| 查看所有订单 | ✅ | ✅ | ✅ |
| 新建订单 / 批量导入 | ✅ | ✅ | ❌ |
| 修改订单基本信息 | 全部 | 仅自己录入的 | ❌ |
| 生产工序打卡 | 全部 | ❌ | 仅自己负责的订单 |
| 修改/删除打卡记录 | 全部 | 仅自己的 | 仅自己的 |
| 创建/删除员工、改职位、增减职位 | ✅ | ❌ | ❌ |
| 增减自定义字段 | ✅ | ❌ | ❌ |
| 导出 Excel | ✅ | ❌ | ❌ |
| 一对一私聊 | ✅ | ✅ | ✅ |

说明：

- 一个订单由**一个下厂员**从面料到包装全程负责；别人的订单只能看，不能打卡。
- 业务员可以更新「订单明细」板块里的面料进度、绣印进度。
- **管理员可以用下拉菜单直接修改任何人的职位，但不能修改自己的职位**；管理员账号不可被删除。
- **职位可以自定义**：除内置的「业务员」「下厂员」外，管理员可以新增职位（如「跟单主管」「质检员」），新增时选一套权限模板（业务员权限 / 下厂员权限），因此不会出现权限真空。还有人担任的职位不能被删除。
- 删除员工是软删除：账号无法再登录，但其历史打卡记录仍完整保留。离职后手机号可以重新用于新账号（返聘场景）。

## 主要功能

1. **登录**：手机号 + 密码，无短信验证码。忘记密码只能找管理员在后台重置，或登录后自己在「我的」里改（不提供公网自助改密，防止被拿手机号盗号）。
2. **管理后台**：创建员工、下拉改职位、重置密码、删除员工（二次确认）。
3. **订单列表**：按季节 / 业务员 / 下厂员 / 货号款式名搜索筛选，卡片显示最新一条打卡。
4. **订单详情**：四大板块 —— 一、订单明细　二、生产明细　三、验货问题　四、跟单小结。顶部大抬头合并显示「款式名 + 款式」，款式图放在右上角。
5. **打卡**：进度类字段像日志一样一条条往下加，**自动记录打卡人姓名和时间**，时间倒序排列，可回看每天情况。「生产进度」里主厂自动带入生产明细选的生产厂，不用重复选；下面的**加工点由下厂员自己按需添加、命名、打卡**（有的订单有外发点、有的没有，不强制预设选项），管理员可删除。
6. **照片**：款式图、每条打卡记录、验货问题、跟单小结都能加照片，**数量不限**，点击可逐张放大查看（左右翻页、**双指缩放/拖动/双击还原**，页面本身仍锁定缩放不受影响）。上传前手机端自动压缩（长边≤2000、约几百 KB），省空间也加载快。
7. **批量导入**：直接上传 **Excel(.xlsx/.xls)** 或 **CSV(.csv/.txt)**，也可以把表格内容复制粘贴进来。Windows 版 Excel 存的 GBK 编码 CSV 会自动识别，不会中文乱码。识别后会**把内容填入可编辑表单**，逐项确认修改后再导入，不会直接入库。
8. **导出**：管理员一键导出全部订单为真实 `.xlsx` 文件。
9. **自定义字段**：管理员可在「订单明细」「生产明细」里增减字段，不是写死的固定表单。字段类型支持文本 / 进度打卡 / 日期 / 数字 / 下拉菜单。
10. **季节**：按当前中国时间自动生成 SS/FW 选项（上一年至后两年），新建订单和列表筛选都用同一份选项。
11. **一对一私聊**：像微信一样选联系人聊天，只有你们两人能看到。**支持发图片和文件**（jpg/png/pdf/Excel/Word/zip 等，单个 20MB 以内）。未读消息在 Tab 上显示红点，进入会话自动标记已读（4~10 秒轮询，规模小无需 WebSocket）。
12. **打卡记录**：在「我的账号」里查看自己的全部打卡；管理员可在「管理后台」点员工的「查看打卡」查看任何人的记录。
13. **验货问题**：不再要手动选日期，提交即用服务器时间。**「发现问题」只能业务员/管理员写，「整改情况」只能本单负责下厂员/管理员写**，双方各自维护自己的一栏，互不能改对方的内容；漏填或需要补充时，双方都能加「补充说明」，累加不覆盖。

## 支持的文件格式

| 场景 | 支持格式 | 大小上限 |
|---|---|---|
| 批量导入订单 | `.xlsx` `.xls` `.csv` `.txt`，或直接粘贴表格内容 | 10 MB |
| 款式图（相册，可多张） | 任意图片（jpg / png / webp / heic 等），上传前自动压缩 | 8 MB |

## 像 App 一样安装（PWA）

系统是一个 PWA，手机上可以「添加到主屏幕」，之后点开就是**全屏运行、有独立图标**，跟原生 App 一样，不显示浏览器地址栏。

- **iPhone（Safari）**：打开网址 → 分享按钮 → 「添加到主屏幕」
- **安卓（Chrome）**：打开网址 → 右上菜单 → 「安装应用 / 添加到主屏幕」
- **电脑（Chrome/Edge）**：地址栏右侧会出现「安装」图标

登录页和「我的」页（仅手机/平板显示，电脑不显示）都有「📲 安装到手机」按钮：安卓/桌面 Chrome 点一下直接弹系统安装框；iPhone 会显示图文步骤教你添加到主屏。

Service Worker 会缓存界面外壳，二次打开秒开、弱网也能进；业务数据始终走网络，保证是最新的。

## 界面

- **移动优先**：底部 Tab 栏（订单 / 聊天 / 管理 / 我的），屏幕宽于 820px 时 Tab 栏自动移到顶部
- 参照 iOS 的分组列表（inset grouped）、系统字体、44px 触摸目标、大圆角与毛玻璃标题栏
- 日期一律显示中文「2026年8月15日」，打卡时间显示「7月19日 17:30」
- 日期和文件选择都用中文按钮包了一层（浏览器原生控件会显示英文 Choose File 和 yyyy/mm/dd），
  底层仍是原生控件，手机上照样调起系统日期轮和相册
- 主色沿用韩式蓝；自动适配深色模式
- 纯 CSS 实现，没有引入任何 UI 框架，因此无需构建步骤

## 登录状态

登录后签发的令牌**不设过期时间**，只要不主动点「退出登录」就一直保持，手机上不用反复登录。
账号被管理员删除时会立即失效。

## 技术栈

- **后端**：Node.js + Express，SQLite（Node 22 内置 `node:sqlite`，零原生依赖）
- **认证**：bcrypt 密码哈希 + JWT
- **前端**：原生 HTML/CSS/JS 单页应用，无需构建步骤
- **Excel**：SheetJS（使用官方 CDN 发行版，`npm audit` 无漏洞）

### 目录结构

```
scripts/
  init-admin.js  正式启用前清空演示数据、创建管理员
server/
  index.js    Express 启动、静态资源、SPA 兜底
  db.js       SQLite 建表与演示数据
  auth.js     密码哈希、JWT、登录中间件、权限判定
  routes/     全部 API 路由，按功能一个文件（index.js 负责按顺序挂载）
    session.js 登录、启动数据、改密码      users.js     员工账号、历史打卡
    settings.js 字段 / 工厂 / 季节 / 职位   orders.js    订单、打卡记录、加工点、验货
    chat.js    私聊和附件                  notifications.js 应用内通知、推送订阅
    uploads.js 照片上传                    import.js / export.js 批量导入 / 导出
    helpers.js 多个文件共用的辅助函数
  push.js     系统推送投递
public/
  index.html  页面骨架，按顺序引入 js/ 下的脚本
  styles.css  样式（韩式蓝，支持深色模式）
  sw.js       Service Worker（离线缓存）
  js/         前端脚本，按功能一个文件，详见下表
test/
  run.js      测试入口（临时数据库+随机端口，不影响正式数据）
```

### 前端脚本（public/js/）

没有打包工具，就是普通 `<script>` 按 `index.html` 里的顺序依次加载，所有文件共用全局变量。
页面上的 `onclick="A.xxx()"` 都对应 `A` 上的方法，`A` 在 `state.js` 里创建，各功能文件用 `Object.assign(A, {...})` 把自己的方法挂上去。

| 想改什么 | 看这个文件 |
|---|---|
| 全局状态、常量 | `state.js` |
| 小工具（转义、日期格式、提示条）、请求服务端 | `utils.js`、`api.js` |
| 谁能看到 / 编辑什么 | `perms.js`（只控制显示，真正的规则在服务端 `auth.js`） |
| 弹窗、表单里的下拉 / 日期 / 多选工厂 | `modal.js`、`fields.js` |
| 页面框架：标签栏、电脑端侧栏、跳转 | `layout.js` |
| 照片选择 / 压缩 / 上传、大图查看器 | `photos.js`、`lightbox.js` |
| 登录、欢迎页 | `auth.js` |
| 订单列表 / 新建 / 详情 | `order-list.js`、`order-new.js`、`order-detail.js` |
| 验货（问题、整改） | `inspection.js` |
| 打卡记录、聊天、消息通知 | `punch-logs.js`、`chat.js`、`notifications.js` |
| 管理后台（人员、权限、表单配置、导出） | `admin.js` |
| 批量导入（读 Excel / 预览确认） | `import-xlsx.js`、`import.js` |
| 「我的」页、安装到手机 / 系统推送 | `account.js`、`pwa.js` |
| 下拉刷新、电脑端拖放粘贴 | `pull-refresh.js`、`drop-paste.js` |
| 启动 | `main.js`（必须最后加载） |

**新增或改名脚本时**：在 `index.html` 里加上（注意顺序），同时登记到 `sw.js` 的 `SHELL` 并把 `CACHE` 版本号加 1，否则手机上会用旧缓存；`npm test` 里有检查，漏了会报错。

### 数据存储

- `users` 账号表；手机号仅在**未删除**账号之间唯一（软删除后可重新启用）
- `settings` 键值表，存自定义字段、工厂下拉选项、职位定义
- `messages` 私聊消息（发送人、接收人、内容、时间、已读时间）
- `orders` 每个订单一行，业务数据以 JSON 存储；时间统一为毫秒时间戳
